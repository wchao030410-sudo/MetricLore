# 架构说明

```text
浏览器
  ├─ 指标目录 / 语义模型 / Wiki 检索 / 知识本体
  └─ Agent 问答 / Agent Trace
          │
          ▼
Node HTTP 服务
  ├─ SkillRegistry：声明式能力边界与工具白名单
  ├─ AgentRuntime：能力解析、函数调用循环、预算与公开轨迹
  ├─ ToolRegistry：Wiki、图谱、语义查询、证据和校验工具
  ├─ WikiIndex + Ontology：结构化实体、关系、检索与追踪
  ├─ SemanticLayer：指标/维度白名单与参数化 SQL
  ├─ SQLite：合成事实数据
  └─ OpenAI-compatible LLM（可选，在允许工具内执行函数调用）
```

## 决策

1. **本地优先**：默认不调用外部服务，没有 API Key 也能运行确定性工作流。
2. **Skill 约束工具**：模型只能看到当前 Skill 的工具白名单，运行时限制最大步骤并拒绝重复调用。
3. **语义层拥有 SQL**：LLM 不生成或执行任意 SQL，只能选择注册指标和维度。
4. **知识与数据分路**：口径问题先查 Wiki，数值问题走指标查询，分析问题在数据结果上做保守描述。
5. **证据先于表达**：最终答案附带来源与公开执行轨迹；没有额外证据时，不把相关性写成原因。

## 当前限制

- 只连接一个 SQLite 事实表。
- 自然语言日期识别仅覆盖“近 N 天”等基础表达。
- Wiki 当前使用本地词项、别名和一跳图谱关系，没有向量索引或 FTS5。
- 没有用户、租户、行列权限与持久化审计。

这些限制让开源演示保持可读和可启动。扩展到生产环境时，可以替换数据库适配器与检索器，但应保留语义白名单和证据边界。
