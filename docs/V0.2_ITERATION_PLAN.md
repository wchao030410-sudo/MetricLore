## 2. 版本目标

v0.2 聚焦三个用户可直接感知的能力：

1. **Wiki Builder**：批量导入自己的文档，生成带来源和本体关系的 Wiki。
2. **多轮 Agent 编排**：在连续对话中继承指标、时间、维度、筛选条件和业务对象，并根据任务组合 Skill。
3. **Agent Workbench**：围绕“构建知识—提问—查看执行—核验证据—继续追问”重构前端。

README 的新增卖点将在对应功能实现并通过验收后发布：

> Drop in your documents. MetricLore extracts business entities, builds an ontology-backed Wiki, and makes the knowledge available to a governed data agent.

## 3. 目标用户旅程

```text
创建本地工作区
  → 导入文件夹 / ZIP / 多个文档
  → 查看解析和知识抽取进度
  → 审核候选实体、关系与冲突
  → 发布 Wiki 并更新索引
  → 发起问题
  → 查看 Agent 计划、工具进度与证据
  → 围绕同一指标和范围继续追问
```

## 5. 功能范围

### 5.1 Wiki Builder

目标流程：

```text
Upload
  → Parse
  → Chunk with source locators
  → Extract entities and relations
  → Validate ontology
  → Detect duplicates and conflicts
  → Human review
  → Publish versioned Wiki
  → Refresh FTS and graph
```

v0.2 P0 文件类型：

- Markdown、TXT、HTML
- 文本型 PDF、DOCX
- CSV、XLSX 数据字典
- SQL
- ZIP 与文件夹批量导入

后续增强：扫描件 OCR、图片复杂表格、音视频、云盘与在线文档连接器。

关键要求：

- 确定性解析保留文件、页码、章节、行号、工作表等来源定位。
- 可选 LLM 提取实体、定义、别名、业务规则和关系。
- 所有 LLM 输出通过 Ontology Schema 校验。
- Review Queue 支持编辑、合并、批准、驳回和批量操作。
- 已验证页面通过冲突流程更新，不被自动覆盖。
- 发布后索引热更新，运行中的服务立即可检索。
- 上传实施类型白名单、大小限制、ZIP 路径穿越和 ZIP bomb 防护。
- 云端模型抽取前展示数据传输范围。

### 5.2 多轮 Agent 编排

持久化对象：

- conversations
- messages
- conversation_context
- agent_runs
- agent_run_events
- tool_calls
- evidence_records

结构化上下文至少包含：

- metrics
- dimensions
- time range
- filters
- referenced Wiki entities
- pending clarification

必须覆盖的对话：

```text
用户：近 14 天收入怎么样？
用户：那按地区拆一下。
用户：华东为什么下降？
用户：这个指标口径是什么？
```

编排从“单请求选择一个 Skill”升级为可检查的 Skill Plan。计划记录目标、上下文、步骤、预算、证据要求和完成条件。多个候选指标进入 `NEEDS_CLARIFICATION`，用户选择后恢复原计划。

### 5.3 Agent Workbench

每条 Assistant 消息包含：

- 回答正文
- 指标、维度、筛选和时间范围
- 图表 / 表格切换
- 可折叠的公开执行过程
- Skill 与工具状态
- 引用和证据
- 继续追问建议
- Stop、Retry、Edit and resend

公开执行过程展示 Agent 的任务计划、上下文继承、Skill、工具、范围和校验状态；模型私有推理不进入 UI。

流式事件：

```text
run.started
plan.created
skill.started
skill.completed
tool.started
tool.completed
evidence.added
answer.delta
validation.completed
clarification.required
run.completed
run.failed
run.cancelled
```

### 5.4 其他交互改进

- Trace 从独立页面迁移到对应消息，右侧 Context Panel 提供完整详情。
- 对话持久化，支持新建、继续、重命名和删除。
- 来源从文件路径升级为可点击引用与原文定位。
- Ontology 卡片列表升级为可搜索、筛选和缩放的关系图。
- Wiki 增加目录树、页面详情、反向关系和来源查看。
- 指标目录增加搜索、类型筛选和血缘入口。
- 表格支持排序、CSV 导出；分析结果支持 Markdown 导出。
- 增加首次使用引导、加载状态、取消、重试和诊断错误卡片。
- 显示当前模型模式、数据源和 Wiki 索引状态。

## 6. 视觉方向

v0.2 采用“研究工作台 + 数据控制台”的视觉语言：

- 暖灰工作区、深墨导航和高对比正文。
- 电光绿表示运行状态，蓝色表示数据查询，琥珀色表示知识审核，红色表示失败与冲突。
- 减少大圆角与装饰性阴影，用网格、分栏和清晰层级组织高密度信息。
- 动效集中在知识构建进度、Agent 执行路径和图谱展开。
- 形成可识别的视觉记忆：从问题、Skill、工具到证据逐步点亮的执行路径。

## 9. 发布门槛

### Wiki Builder

- 单任务至少处理 50 个文件或 100 MB ZIP。
- 支持格式解析成功率达到 95%。
- 已发布实体来源覆盖率 100%。
- PDF 定位到页码，DOCX/Markdown 定位到章节。
- 发布后索引热更新。
- 失败任务可诊断、可重试。

### Multi-turn Agent

- 至少 30 组多轮评测。
- 指标、时间、维度上下文继承准确率达到 90%。
- 会话之间上下文隔离率 100%。
- 澄清后可以恢复原运行计划。
- 每条回答拥有独立 Run、Trace 和 Evidence。

### Frontend

- 首页可以进入 Wiki Builder 或新建对话。
- 用户可以完成导入、审核、发布和提问闭环。
- Trace 在消息内实时展示。
- 引用可以打开原文定位。
- 图表和表格可以切换。
- 支持停止、重试和错误恢复。

### Engineering

- 原有测试、健康检查、评测和审计继续通过。
- 新增数据迁移、摄入、多轮、SSE 和前端关键流程测试。
- CI 覆盖新增门禁。
- 敏感数据与云端模型传输边界明确。
