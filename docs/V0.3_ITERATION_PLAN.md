## 2. 版本目标

v0.3 的目标是把产品从"演示闭环"推进到"可自用闭环"。任何人都可以：

```text
克隆项目 → 配置自己的 API Key → 自建知识库（v0.2 已支持）
  → 上传自己的数据（CSV / Excel）
  → 注册自己的语义模型与指标
  → 让 AI 自动选择模型问数、分析
  → 用评测验证自己数据的准确率与回答质量
```

v0.2 已经打通了知识侧（文档 → Wiki → 审核 → 发布 → 检索）；v0.3 补齐数据侧缺失的中间层：**数据接入、数据工作区、语义模型注册闭环，以及让 AI 在多模型之间自动选择**。

| 问数使用的模型 | ⚠️ 只能手动切换"当前模型" | AI 跨模型自动路由 |

## 4. 设计原则

1. **数据上传不等于放开任意 SQL。** 上传生成的事实表仍然只能通过语义层访问；模型与提示词都不能绕过注册指标直接查询。
2. **安全建表。** 用户提供的表名、列名只作为业务名保存，物理表使用内部安全标识（`user_<uuid>`）；类型推断结果在上传预览中可微调，确认后才建表。
3. **删除保护。** 被语义模型引用的数据源禁止删除，提示先删除其模型，避免悬空引用。
4. **自动路由有边界。** AI 只在能明确判断时自动选择模型：术语唯一命中某模型即自动路由；多模型命中时优先当前会话/当前模型；仍有多义才澄清，不猜测。
5. **本地优先。** 上传的数据只保存在本地 SQLite，不发送到任何外部服务；LLM 相关能力仍需用户显式配置 API Key。
6. **信任可验证。** 用户自己注册的模型同样进入数据准确率评测与运行快照，让"我自己的数据准不准"可检查。

## 5. 功能范围

### 5.1 数据工作区（Data Workspace）

- 左侧导航新增「数据」入口。
- 数据源列表：内置表（`daily_metrics`）与用户数据源，展示行数、列数、来源与创建时间。
- 数据源详情：前 N 行预览、列类型、候选时间字段与维度、注册状态。
- 删除数据源：被语义模型引用时禁止删除并给出指引。
- 提供一键体验示例：内置一份示例 CSV，让用户 1 分钟走通"上传 → 建模型 → 问数"。

### 5.2 CSV / Excel 上传建表

- 支持 CSV（RFC 4180）与 XLSX。
- 自动推断：数值/整数/文本/日期列、时间字段识别、文本列作为候选维度。
- 上传预览可微调：列名、列类型、时间字段、维度勾选。
- 确认后建表并批量写入，限制上传大小、行数与列数。
- 复用 v0.1 已有的 CSV/XLSX 解析与 multipart 上传能力，不引入新依赖。

### 5.3 语义模型注册闭环

- 数据源详情页提供「基于此表创建语义模型」：自动预填时间字段与维度候选，沿用现有注册流程。
- 模型建好后引导注册第一个指标（原子或派生），随后即可问数。
- 用户旅程：上传数据 → 建模型 → 注册指标 → 提问 → 评测。

### 5.4 评测联动

- `data-accuracy` 套件对**当前用户模型**独立重算比对（逻辑已具备，补齐对自定义表/模型的覆盖）。
- 用户模型的 schema 纳入评测运行快照与历史，可回溯对比。
- 数据工作区提供该模型的评测结果入口。

### 5.5 多模型自动路由

- 指标/维度术语跨**所有**语义模型匹配，命中返回 `(modelId, metricKey)`。
- 唯一命中 → 自动路由到该模型；多模型命中 → 优先当前会话/当前模型；仍有多义 → 澄清。
- 多轮上下文记录 `modelId`，追问继承上一轮模型。
- 语义查询工具接受 `modelId`（底层 `buildQuery` 已支持，补齐解析与工具传递）。
- LLM 模式下目录工具展示全部模型，模型可自行选择；确定性解析作为兜底。
- 保留「当前模型」作为默认与评测基准。

## 6. 已确认的设计决策

1. **删除保护**：被语义模型引用的数据源禁止删除（提示先删除模型）。✅ 已确认
2. **一键体验示例**：数据工作区放置内置示例 CSV。✅ 已确认
3. **建表交互**：自动推断 + 可微调。✅ 已确认
4. **数据接入形态**：MVP 只做 CSV/Excel 上传；SQLite 文件导入、DuckDB 与网络数据库连接器整体后置到待办。✅ 已确认

## 7. 目标接口

```text
POST   /api/data/sources            # multipart 上传 CSV/XLSX，自动推断并建表
GET    /api/data/sources            # 数据源列表
GET    /api/data/sources/:id        # 详情 + 预览 + 推断结果
PATCH  /api/data/sources/:id        # 应用微调后的建表参数（或随 POST 提交）
DELETE /api/data/sources/:id        # 删除数据源（被引用时 409）

POST   /api/semantic/models         # 既有：基于数据表注册语义模型
POST   /api/semantic/models/:id/activate   # 既有：设为当前模型
POST   /api/semantic/metrics        # 既有：注册指标（携带 modelId）
GET    /api/catalog?modelId=        # 既有：按模型获取目录
POST   /api/query                   # 既有：语义查询（新增可选 modelId）

GET    /api/evaluation              # 既有：评测报告、运行、快照（纳入用户模型）
```

现有 `/api/knowledge/*`、`/api/conversations/*`、`/api/wiki/*` 接口保持兼容。

### M1：数据工作区与上传建表

交付：

- `data_sources` 表与迁移。
- CSV/XLSX 上传、类型推断、预览与可微调、建表与批量写入。
- 数据源列表、详情、预览与删除（引用保护）。
- 一键体验示例 CSV。
- 数据工作区前端页面。

验收：用户可从零上传一份 CSV/Excel，在预览中调整列类型与维度后成功建表；表在数据源列表可见、可预览、可删除；被语义模型引用的表删除被阻止；示例 CSV 一键走通上传。

### M2：语义模型注册闭环

交付：

- 数据源详情「基于此表创建语义模型」，预填时间字段与维度。
- 模型创建后的指标注册引导（原子/派生）。
- 前端将「上传 → 建模型 → 注册指标 → 问数」串成连续旅程。

验收：从一张用户上传的表创建语义模型并注册指标后，Agent 可立即用该模型问数；语义模型页可切换查看、设为当前模型。

### M3：评测联动

交付：

- `run-data-evals.mjs` 对当前用户模型独立重算比对。
- 用户模型 schema 纳入评测运行快照。
- 数据工作区与评测页展示用户模型的数据准确率结果。

验收：激活用户模型后运行评测，data-accuracy 以用户表为基准输出准确率、查询耗时与数值比对数；运行历史可回溯用户模型快照。

### M4：多模型自动路由

交付：

- 跨模型指标/维度匹配，命中返回 `(modelId, metricKey)`。
- 唯一命中自动路由、多模型命中优先级、歧义澄清。
- 多轮上下文 `modelId` 继承。
- 查询工具与 LLM 目录工具支持 `modelId`。

验收：提问只存在于模型 B 的指标时自动使用模型 B；同名指标在多模型时优先当前模型、歧义时澄清；追问继承同一模型；确定性路径与 LLM 路径均覆盖。

## 9. 发布门槛

- 从全新 clone 可以在 10 分钟内完成一次"上传数据 → 建模型 → 问数 → 评测"。

- 删除保护：被引用数据源删除返回明确错误。
- 自动路由：唯一命中路由准确率 100%；多模型歧义时进入澄清；上下文 modelId 继承准确率 100%。
- 既有能力不回归：v0.2 全部评测与测试继续通过。

## 10. 范围外与待办

- SQLite 文件导入（上传 `.db` 文件、选表复制）：MVP 不做，待办。
- DuckDB 连接器（本地大数据/Parquet）：待办。
- PostgreSQL / MySQL 等网络数据库连接器：待办（含凭据管理、连接配置 UI、查询代理）。
- 向量检索与重排序、数据质量规则引擎、可视化分析：待办。
- 任意 SQL 访问：永不放开。
