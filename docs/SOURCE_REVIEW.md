# 三个源工程的系统梳理

本文件记录本地化时读取到的能力边界。压缩包中的 Agent/开发说明只作为源工程背景，没有被当作本次操作指令执行。

## 源工程 A：前端组件库

源工程是一个 React、TypeScript、Ant Design 的私有组件 monorepo，约 3,024 个文件。与目标直接相关的模块包括：

| 源模块 | 能力 | 本项目落点 |
|---|---|---|
| `metrics-management` | 原子/派生指标表单、指标列表 | 指标目录与 `semantic-model.json` |
| `metrics-overview` | 指标概览 | Web 指标卡片 |
| `trend-analysis` | 指标选择、趋势图、明细 | Agent 趋势查询与结果表 |
| `dimension-analysis` | 维度选择、分组分析 | 查询 API 的 `dimensions` 与 `filters` |
| `logic-table-management` | 逻辑表、字段与维度配置 | 语义模型的 table、column、dimension 映射 |

没有直接复制这些组件，因为它们依赖内部接口、远程组件发布体系和大量与数据 Agent 无关的业务组件。开源版保留交互概念，使用原生 Web 界面重新实现。

## 源工程 B：Enterprise LLM-Wiki

源工程包含 Wiki 内容、Wiki MCP、知识摄入流水线和较完整的 Wiki Agent。与目标直接相关的设计包括：

- Raw / Wiki / Outputs 分层和 Markdown 知识页面。
- Wiki 检索、语义假设、指标定义、表语义、图谱关系和回答证据。
- Agent 的单一工具循环、Wiki 工具、取数工具、分析方法和安全报告。
- 知识摄入中的 SQL 解析、实体校验、去重、冲突检测、关系建议与健康检查。

源工程同时包含单点登录、内部通讯、内部 Wiki 发布、评测后台、值班系统、团队映射和内部 MCP。开源版将核心收敛为 `WikiIndex + DataAgent`，保留“检索有来源、数据走确定性工具、模型负责表达”的边界，删除组织和部署专用能力。

## 源工程 C：指标与数据查询后端

源工程是多模块 Java DDD 项目，约 611 个文件。核心能力包括：

- 指标元数据、逻辑表、维度、主题域与业务域管理。
- 原子指标加载、复合表达式计算、分桶聚合、同比和环比。
- 维度筛选、动态 SQL、查询执行日志与指标快照。
- SQL 注入字符检查和部分输入约束。

原工程使用内部 Spring Boot 父依赖、日志、RPC、配置中心、缓存、消息队列、数据访问框架和内部包名，无法在公网环境直接构建。开源版用 SQLite 和 Node 标准库重写最小可运行内核：原子指标、比率型复合指标、维度过滤、日/周/月粒度与参数绑定。

## 能力取舍

| 能力 | 结果 | 原因 |
|---|---|---|
| 指标目录与口径 | 保留 | 展示数据治理核心 |
| 原子/复合指标 | 保留 | 问数计算基础 |
| 维度与时间粒度 | 保留 | 支撑趋势与拆分 |
| Wiki 检索与引用 | 保留 | 支撑口径问答 |
| 自然语言问数/分析 | 保留 | 项目主入口 |
| 任意 SQL | 删除 | 安全和可治理性不足 |
| 企业 SSO、通讯、值班 | 删除 | 组织专用且无法本地部署 |
| 内部中间件与 RPC | 删除 | 公网不可获得 |
| 真实业务元数据与评测集 | 删除 | 可能含内部知识与数据 |
| 复杂发布与运维脚本 | 删除 | 绑定内部基础设施 |
| 通用摄入流水线 | 暂不纳入运行时 | 可在后续独立成 CLI，避免首版过重 |
